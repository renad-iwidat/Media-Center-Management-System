## نظرة عامة

تم بناء نظام تسجيل دخول موحد يربط نظام الأخبار بنظام الإدارة. الموظف يسجل دخول مرة واحدة باستخدام بيانات حسابه في نظام الإدارة، والتوكن يُستخدم مع جميع الطلبات في نظام الأخبار.

### الفوائد
- ✅ موظف واحد = حساب واحد
- ✅ تسجيل دخول موحد
- ✅ تتبع العمليات برقم المستخدم
- ✅ صلاحيات موحدة
- ✅ إحصائيات موحدة

## تدفق تسجيل الدخول

### الخطوة 1: عرض صفحة تسجيل الدخول

```
المستخدم يفتح نظام الأخبار
↓
الفرونت يتحقق من وجود توكن في localStorage
↓
إذا لا يوجد توكن → عرض صفحة LoginPage
```

### الخطوة 2: إدخال البيانات

```
المستخدم يدخل:
- البريد الإلكتروني: a.moqadi@najah.edu
- كلمة المرور: a.mo1234
↓
يضغط على زر "دخول"
```

### الخطوة 3: إرسال الطلب

```
الفرونت يرسل:
POST https://media-center-management-system.onrender.com/api/auth/login
{
  "email": "a.moqadi@najah.edu",
  "password": "a.mo1234"
}
```

### الخطوة 4: التحقق والرد

```
السيرفر يتحقق من البيانات
↓
إذا صحيح:
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": {
      "id": 57,
      "name": "أحمد موقدي",
      "email": "a.moqadi@najah.edu",
      "roles": [{ "id": 19, "name": "مخرج" }]
    }
  }
}

إذا خاطئ:
{
  "success": false,
  "error": "Invalid email or password"
}
```

### الخطوة 5: حفظ التوكن

```
الفرونت يحفظ:
- التوكن في localStorage['authToken']
- بيانات المستخدم في localStorage['currentUser']
```

### الخطوة 6: جلب بيانات المستخدم الكاملة

```
الفرونت يرسل:
GET https://media-center-management-system.onrender.com/api/auth/me
Header: Authorization: Bearer TOKEN
```

### الخطوة 7: الرد مع البيانات الكاملة

```
السيرفر يرسل:
{
  "success": true,
  "data": {
    "id": 57,
    "name": "أحمد موقدي",
    "email": "a.moqadi@najah.edu",
    "work_days": "الأحد,الاثنين,الثلاثاء,الأربعاء,الخميس",
    "start_time": "08:00",
    "end_time": "16:00",
    "is_active": true,
    "last_login": "2026-04-28T10:00:00.000Z",
    "roles": [{ "id": 19, "name": "مخرج" }],
    "permissions": ["orders.view", "tasks.view", "shootings.view", "content.view", "content.create", "programs.view"]
  }
}
```

### الخطوة 8: عرض الواجهة الرئيسية

```
الفرونت يحفظ البيانات الكاملة
↓
يعرض الواجهة الرئيسية
↓
يعرض اسم المستخدم والدور
```

## ربط المهام برقم المستخدم

### السيناريو الأول: شغل ضمن مهمة

```
1. المدير ينشئ أوردر "نشرة أخبار الساعة 8" بنظام الإدارة
2. المدير يعمل مهمة "تحرير أخبار" ويعينها للمحرر
3. المحرر يفتح المهمة — يشوف زر "افتح نظام الأخبار"
4. الفرونت يفتح رابط:
   https://news-system.onrender.com/editorial?task_id=45
5. نظام الأخبار يأخذ task_id من الرابط
6. المحرر يحرر ويوافق على الأخبار
7. كل عملية تُحفظ مع:
   - task_id = 45
   - user_id = 57 (من التوكن)
8. الخبر ينشر ويروح لجدول published_items مع task_id و approved_by
9. نظام الإدارة يسحب المنشورات الجديدة ويحولها لمحتوى مربوط بالمهمة
10. مؤشرات الأداء تتحدث تلقائي
```

### السيناريو الثاني: شغل بدون مهمة

```
1. المحرر يفتح نظام الأخبار مباشرة (بدون مهمة)
2. لا يوجد task_id في الرابط
3. المحرر يحرر أخبار أو يستخدم أدوات الذكاء الاصطناعي
4. كل عملية تُحفظ مع:
   - task_id = NULL
   - user_id = 57 (من التوكن)
5. العمليات تُسجل باسم الموظف بس مش مربوطة بأوردر معين
6. نظام الإدارة بيقرأ من الجداول وبيحسب شو عمل الموظف
7. بيظهر بمؤشرات أداء الموظف — بس مش مربوط بأوردر معين
```

## الملفات المتعلقة

### Frontend

#### صفحة تسجيل الدخول
- **الملف**: `frontend/src/components/auth/LoginPage.tsx`
- **الوظيفة**: عرض نموذج تسجيل الدخول
- **المكونات**:
  - حقل البريد الإلكتروني
  - حقل كلمة المرور
  - زر تسجيل الدخول
  - عرض الأخطاء

#### API Service
- **الملف**: `frontend/src/services/api.ts`
- **الدوال**:
  - `api.login(email, password)` - تسجيل الدخول
  - `api.getMe()` - جلب بيانات المستخدم
  - `api.logout()` - تسجيل الخروج
  - `getAuthToken()` - الحصول على التوكن
  - `setAuthToken(token)` - حفظ التوكن
  - `getCurrentUser()` - الحصول على بيانات المستخدم

#### التطبيق الرئيسي
- **الملف**: `frontend/src/App.tsx`
- **التعديلات**:
  - إضافة منطق المصادقة
  - عرض صفحة تسجيل الدخول إذا لم يكن المستخدم مسجل دخول
  - عرض اسم المستخدم والدور
  - زر تسجيل الخروج

#### متغيرات البيئة
- **الملف**: `frontend/.env`
- **المتغيرات**:
  - `VITE_MANAGEMENT_API_URL` - رابط سيرفر الإدارة
  - `VITE_API_URL` - رابط سيرفر الأخبار

### Backend

#### نقاط وصول المصادقة
- **الملف**: `src/routes/auth/auth.routes.ts`
- **النقاط**:
  - `POST /api/auth/login` - تسجيل الدخول
  - `GET /api/auth/me` - جلب بيانات المستخدم

#### وسيط المصادقة
- **الملف**: `src/middleware/auth.ts`
- **الوظائف**:
  - `authenticate()` - التحقق من التوكن
  - `requirePermission()` - التحقق من الصلاحيات
  - `authorize()` - التحقق من الدور (قديم)

#### خدمة المصادقة
- **الملف**: `src/services/management/AuthService.ts`
- **الدوال**:
  - `AuthService.login()` - تسجيل الدخول
  - `AuthService.getMe()` - جلب بيانات المستخدم
  - `AuthService.verifyToken()` - التحقق من التوكن

#### خدمة الصلاحيات
- **الملف**: `src/services/management/PermissionService.ts`
- **الدوال**:
  - `PermissionService.getUserPermissions()` - جلب صلاحيات المستخدم
  - `PermissionService.userHasPermission()` - التحقق من صلاحية معينة

## الأمان

### التوكن
- يُحفظ في `localStorage` (يمكن الوصول إليه من JavaScript)
- يُرسل مع كل طلب في هيدر `Authorization`
- ينتهي بعد 24 ساعة (قابل للتعديل في `.env`)
- يُتحقق من صحته على السيرفر

### كلمة المرور
- لا تُحفظ في الفرونت
- تُرسل مرة واحدة فقط عند تسجيل الدخول
- تُشفر بـ bcryptjs على السيرفر
- لا تُرسل مع أي طلب آخر

### الصلاحيات
- تُجلب من السيرفر بعد تسجيل الدخول
- تُستخدم للتحكم في ما يراه المستخدم بالواجهة
- تُتحقق أيضاً على السيرفر (لا تعتمد على الفرونت)
- تُحدث مع كل طلب

## استكشاف الأخطاء

### "فشل تسجيل الدخول"
- تحقق من البريد الإلكتروني وكلمة المرور
- تأكد من أن السيرفر يعمل
- تحقق من متغيرات البيئة
- تحقق من الاتصال بقاعدة البيانات

### "فشل جلب بيانات المستخدم"
- تأكد من أن التوكن صحيح
- تأكد من أن السيرفر يعمل
- تحقق من الصلاحيات
- تحقق من الاتصال بقاعدة البيانات

### "Access denied. No token provided"
- تأكد من أن التوكن محفوظ في localStorage
- تأكد من أن الهيدر يُرسل بشكل صحيح
- جرب تسجيل الدخول مرة أخرى
- امسح localStorage وحاول مرة أخرى

### "Invalid or expired token"
- التوكن انتهى صلاحيته
- جرب تسجيل الدخول مرة أخرى
- امسح localStorage وحاول مرة أخرى

## الخلاصة

تم بناء نظام تسجيل دخول موحد يربط نظام الأخبار بنظام الإدارة. الموظف يسجل دخول مرة واحدة، والتوكن يُستخدم مع جميع الطلبات. كل عملية تُحفظ برقم المستخدم، مما يسمح بتتبع العمليات وحساب الإحصائيات.

الخطوة التالية هي ربط المهام برقم المستخدم وحفظ `task_id` مع كل عملية، بحيث يمكن ربط الأخبار المنشورة بالمهام الأصلية.
