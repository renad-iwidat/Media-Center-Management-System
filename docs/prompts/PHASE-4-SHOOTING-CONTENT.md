# المرحلة 4 — التصوير والمحتوى والأرشيف

## المطلوب

ابنيلي صفحات المحتوى والأرشيف كاملة وشغالة. التصوير مش صفحة منفصلة بالقائمة — التصوير بينشأ من داخل المهمة. والمحتوى بينشأ من داخل التصوير أو من داخل المهمة. صفحة المحتوى بالقائمة هي للبحث والأرشيف وإعادة الاستخدام.

كل زر يشتغل فعلياً مع السيرفر. أي إضافة تنعكس فوراً على الداشبورد. لا تستخدم خطوط عربية مائلة.

**السيرفر:** `https://media-center-management-system.onrender.com`
**كل الطلبات لازم يكون معها:** `Authorization: Bearer TOKEN`

---

## التصوير — من داخل المهمة

التصوير مش صفحة منفصلة بالقائمة الجانبية. التصوير بينشأ من داخل صفحة تفاصيل المهمة.

### كيف بيشتغل
لما المستخدم يفتح مهمة نوعها "تصوير" — بيشوف قسم خاص اسمه "التصوير" فيه:
- إذا ما في تصوير مرتبط — زر "إنشاء حدث تصوير"
- إذا في تصوير — تفاصيل التصوير + المحتوى المنتج منه

### يعني بصفحة تفاصيل المهمة (المرحلة 3) — أضيف قسم جديد:

**قسم التصوير (يظهر لكل المهام):**

جلب التصويرات المرتبطة بالمهمة:
```
GET /api/shootings/task/:taskId
```

إذا في تصويرات — اعرضها: الموقع + الموعد + نوع المصدر + عدد المحتوى.
الضغط على تصوير يفتح تفاصيله (ممكن بنافذة منبثقة أو بقسم يتوسع).

إذا ما في — زر "إنشاء حدث تصوير".

## نموذج إنشاء تصوير جديد

### الحقول
- الأوردر (قائمة منسدلة — إلزامي) — من `GET /api/orders`
- المهمة (قائمة منسدلة — اختياري، تظهر مهام الأوردر المختار) — من `GET /api/tasks/order/:orderId`
- الموقع (نص — إلزامي)
- موعد البداية (تاريخ ووقت — إلزامي)
- موعد النهاية (تاريخ ووقت — اختياري)
- المعدات (قائمة نصية — يضيف ويحذف عناصر)
- الطاقم (قائمة نصية — يضيف ويحذف عناصر)
- نوع المصدر (اختيار: داخلي أو خارجي)
- ملاحظات (نص)

### الربط
```
POST /api/shootings
{
  "order_id": 1,
  "task_id": 5,
  "location": "رام الله",
  "start_time": "2026-05-01T10:00:00",
  "end_time": "2026-05-01T14:00:00",
  "equipment": ["كاميرا سوني", "ميكروفون"],
  "crew": ["عمير", "محمد"],
  "notes": "ملاحظات",
  "source_type": "internal",
  "created_by": USER_ID
}
```

## صفحة تفاصيل التصوير `/shootings/:id`

### جلب التفاصيل الكاملة
```
GET /api/shootings/:id/full
```
بترجع: بيانات التصوير + اسم الأوردر + حالة المهمة + اسم المنشئ + كل المحتوى المنتج من هاد التصوير.

### التصميم — 3 أقسام:

**القسم الأول — معلومات التصوير:**
- الموقع + الموعد + المعدات + الطاقم + نوع المصدر + ملاحظات
- اسم الأوردر (رابط يوصل لصفحة الأوردر)
- حالة المهمة المرتبطة
- اسم المنشئ
- أزرار: تعديل + حذف

**القسم الثاني — المحتوى المنتج:**
- جدول بالمحتوى اللي طلع من هاد التصوير: العنوان + النوع + نوع المخرج (تقرير/سوشال/فيديو/أرشيف)
- إذا ما في محتوى — رسالة "لم يتم إنتاج محتوى بعد"

**القسم الثالث — إنشاء محتوى من التصوير:**
- زر "إنشاء محتوى" — يفتح نموذج
- زر "إنشاء عدة محتويات" — يفتح نموذج الدفعة

## إنشاء محتوى من تصوير (فردي)

### النموذج
- العنوان (نص — إلزامي)
- نوع المحتوى (قائمة منسدلة — إلزامي) — من `GET /api/content/types`
- نوع المخرج (اختيار: تقرير / سوشال / فيديو / أرشيف)
- رابط الملف (نص — اختياري)
- حجم الملف (رقم — اختياري)
- المدة بالثواني (رقم — اختياري)
- الوسوم (قائمة نصية)

### الربط
```
POST /api/content/from-shooting
{
  "shooting_id": 5,
  "title": "تقرير ميداني",
  "content_type_id": 1,
  "created_by": USER_ID,
  "cloud_url": "https://...",
  "file_size": 1024000,
  "duration": 120,
  "tags": ["ميداني"],
  "output_type": "report"
}
```

## إنشاء عدة محتويات من تصوير (دفعة)

### النموذج
- نموذج ديناميكي — المستخدم يضيف عناصر (زر "إضافة محتوى آخر")
- كل عنصر فيه: العنوان + نوع المحتوى + نوع المخرج
- زر "إنشاء الكل"

### الربط
```
POST /api/content/from-shooting/batch
{
  "shooting_id": 5,
  "created_by": USER_ID,
  "items": [
    { "title": "تقرير ميداني", "content_type_id": 1, "output_type": "report" },
    { "title": "مقطع سوشال", "content_type_id": 2, "output_type": "social" },
    { "title": "الفيديو الكامل", "content_type_id": 3, "output_type": "video" }
  ]
}
```

## صفحة المحتوى والأرشيف `/content`

### صفحة واحدة موحدة
هاي الصفحة بتعرض كل المحتوى — الأرشيف هو نفسه بس مفلتر. تبويبين بالأعلى:
- "كل المحتوى" — بدون فلتر أرشيف
- "الأرشيف" — مع فلتر `archived=true`

### البحث والفلترة الموحدة
```
GET /api/content?keyword=مقابلة&type=1&status=2&creator=52&media_unit=1&from=2026-04-01&to=2026-04-30&archived=true&limit=10&offset=0
```
كل المعاملات اختيارية.

### عناصر الفلترة
- حقل بحث بالكلمة المفتاحية
- نوع المحتوى (قائمة منسدلة) — من `GET /api/content/types`
- المنشئ (قائمة منسدلة) — من `GET /api/portal/users`
- الفترة الزمنية (من — إلى)

### جدول المحتوى
- العنوان + النوع + المنشئ + تاريخ الإنشاء + هل نهائي (بادج أخضر) + هل مؤرشف (بادج) + عدد مرات إعادة الاستخدام
- الضغط على صف يفتح التفاصيل

### زر "رفع محتوى جديد"
يفتح نموذج إنشاء محتوى مباشرة (بدون تصوير).

## نموذج إنشاء محتوى مباشرة

```
  "created_by": USER_ID,

  "file_size": 1024000,
  "duration": 120,
  "tags": ["..."]
}
```

## صفحة تفاصيل المحتوى `/content/:id`

### جلب المحتوى
```
GET /api/content/:id
```

### التصميم — 4 أقسام:

**القسم الأول — معلومات المحتوى:**
- العنوان + النوع + المنشئ + تاريخ الإنشاء + رابط الملف + الحجم + المدة
- هل نهائي (بادج) + هل مؤرشف (بادج)
- أزرار:
  - "تعديل" — يفتح نموذج التعديل
  - "تعليم كنهائي" — يظهر فقط إذا مش نهائي. لما يتعلم كنهائي بيتأرشف تلقائي
  - "أرشفة يدوية" — `POST /api/content/:id/archive` مع `{ "archived_by": USER_ID }`
  - "حذف"

**تعليم كنهائي:**
```
PUT /api/content/:id
{ "is_final": true }
```

**القسم الثاني — الوسوم:**
- قائمة الوسوم الحالية (كل وسم بزر حذف)
- حقل إضافة وسم جديد
```
POST /api/content/:id/tags
{ "tag_id": 3 }

DELETE /api/content/:id/tags/:tagId
```

**القسم الثالث — إعادة الاستخدام:**
- عدد مرات إعادة الاستخدام: `GET /api/content/:id/reuse-count`
- تاريخ إعادة الاستخدام: `GET /api/content/:id/reuse-history`
  - جدول: اسم المهمة + مين استخدمه + متى
- زر "إعادة استخدام بمهمة جديدة":
```
POST /api/content/:id/reuse
{ "task_id": 15, "reused_by": USER_ID }
```

**القسم الرابع — المهام المرتبطة:**
- قائمة المهام المرتبطة بهاد المحتوى
- زر "ربط بمهمة":
```
POST /api/content/:id/link-task
{ "task_id": 10, "linked_by": USER_ID, "usage_type": "reference" }
```
- زر "فك ربط":
```
DELETE /api/content/:id/unlink-task/:taskId
```

## الفلو الكامل: تصوير ← محتوى ← أرشيف

```
1. المستخدم ينشئ تصوير مرتبط بأوردر ومهمة
2. بعد التصوير — يفتح تفاصيل التصوير ويضغط "إنشاء محتوى"
3. يعبي النموذج (فردي أو دفعة) — المحتوى بينشأ مربوط بالمهمة تلقائي
4. مؤشرات الأداء بتتحدث تلقائي + إشعار بيوصل لصاحب الأوردر
5. لما المحتوى يصير نهائي — بيتأرشف تلقائي
6. من الأرشيف — ممكن يعاد استخدامه بمهمة جديدة
```
