# المرحلة 6 — إدارة المستخدمين والصلاحيات

## المطلوب

ابنيلي صفحات إدارة المستخدمين والصلاحيات. هاي الصفحات فقط للإدارة (صلاحية `users.manage` و `roles.manage`). كل نموذج يشتغل فعلياً مع السيرفر. لا تستخدم خطوط عربية مائلة.

**السيرفر:** `https://media-center-management-system.onrender.com`
**كل الطلبات لازم يكون معها:** `Authorization: Bearer TOKEN`

---

## صفحة إدارة المستخدمين `/users`

### جلب المستخدمين
```
GET /api/portal/users
```
الرد فيه: الاسم + الإيميل + الدور + أيام العمل

### التصميم
- جدول: الاسم + الإيميل + الدور + أيام العمل + وقت البداية/النهاية + آخر تسجيل دخول
- فوق الجدول: حقل بحث + زر "مستخدم جديد"
- الضغط على مستخدم يفتح تفاصيله

---

### إنشاء مستخدم جديد

```
POST /api/auth/register
{
  "name": "...",
  "email": "...@najah.edu",
  "password": "...",
  "role_id": 11,
  "work_days": "الأحد,الاثنين,الثلاثاء,الأربعاء,الخميس",
  "start_time": "08:00",
  "end_time": "16:00"
}
```

النموذج:
- الاسم (نص — إلزامي)
- الإيميل (نص — إلزامي)
- كلمة السر (نص — إلزامي، 6 حروف على الأقل)
- الدور الأساسي (قائمة منسدلة) — من `GET /api/portal/roles`
- أيام العمل (اختيار متعدد: الأحد، الاثنين، الثلاثاء، الأربعاء، الخميس، الجمعة، السبت)
- وقت البداية (وقت)
- وقت النهاية (وقت)

---

### تفاصيل المستخدم

#### معلومات أساسية
```
GET /api/portal/users/:id/with-role
```
الاسم + الإيميل + الدور + أيام العمل + وقت البداية/النهاية
أزرار: تعديل + تعيين كلمة سر

#### تعديل المستخدم
```
PUT /api/portal/users/:id
{ "name": "...", "email": "...", "work_days": "...", "start_time": "...", "end_time": "..." }
```

#### تعيين كلمة سر
```
POST /api/auth/set-password/:userId
{ "new_password": "..." }
```

---

### أدوار المستخدم

كل مستخدم ممكن يكون عنده أكثر من دور. هاد القسم بيعرض أدواره ويسمح بإضافة وحذف.

#### جلب أدوار المستخدم
```
GET /api/permissions/users/:userId/roles
```
الرد: قائمة الأدوار (الاسم + الوصف)

#### إضافة دور
```
POST /api/permissions/users/:userId/roles
{ "role_id": 9 }
```
الأدوار المتاحة من: `GET /api/portal/roles`

#### حذف دور
```
DELETE /api/permissions/users/:userId/roles/:roleId
```

---

### صلاحيات المستخدم

#### جلب الصلاحيات (مجمعة من كل أدواره)
```
GET /api/permissions/users/:userId/permissions
```
الرد: قائمة أسماء الصلاحيات

#### التصميم
- قائمة الصلاحيات مقسمة حسب الفئة:
  - أوردرات: عرض، إنشاء، تعديل، حذف
  - مهام: عرض، إنشاء، تعيين، تعديل، حذف
  - تصوير: عرض، إنشاء، تعديل
  - محتوى: عرض، إنشاء، تعديل، حذف، أرشفة
  - برامج: عرض، تعديل
  - مستخدمين: عرض، إدارة
  - أدوار: إدارة
  - لوحة التحكم: عرض
  - إعدادات: إدارة
- كل صلاحية بجانبها علامة صح أو إكس (للعرض فقط — الصلاحيات بتتغير بتغيير الأدوار)

---

### مؤشرات أداء المستخدم

```
GET /api/kpi/users/:userId
```

الرد:
```json
{
  "total_tasks_assigned": 30,
  "completed_tasks": 25,
  "pending_tasks": 3,
  "overdue_tasks": 2,
  "average_completion_time": 90,
  "on_time_percentage": 85,
  "content_produced_count": 15,
  "ai_usage_count": 10
}
```

التصميم:
- بطاقات صغيرة: إجمالي المهام + المكتملة + المتأخرة + نسبة الالتزام
- شريط تقدم لنسبة الالتزام بالمواعيد
- عدد المحتوى المنتج + عدد مرات استخدام الذكاء الاصطناعي

## صفحة الصلاحيات `/permissions`

### جلب كل الصلاحيات المتاحة
```
GET /api/permissions
```

### جلب صلاحيات دور معين
```
GET /api/permissions/roles/:roleId
```

### التصميم
- قائمة الأدوار على اليمين
- لما تختار دور — تظهر صلاحياته على اليسار
- الصلاحيات مقسمة حسب الفئة (أوردرات، مهام، محتوى...)
- كل صلاحية بجانبها علامة صح أو إكس

---

## ملاحظات مهمة

- هاي الصفحات فقط للإدارة — إذا المستخدم ما عنده صلاحية `users.manage` أو `roles.manage` ما يشوفها بالقائمة ولا يقدر يوصلها
- الصلاحيات بتتغير بتغيير الأدوار — مش بتعديل الصلاحيات مباشرة
- لما تضيف دور لمستخدم — صلاحياته بتتحدث فوراً (بتتجمع من كل أدواره)
