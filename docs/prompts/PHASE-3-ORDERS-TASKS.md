# المرحلة 3 — الأوردرات والمهام

## المطلوب

ابنيلي صفحات الأوردرات والمهام كاملة وشغالة. كل زر يشتغل، كل نموذج يبعث بيانات حقيقية للسيرفر، كل حالة تتغير فعلياً. أي إضافة أو تعديل لازم ينعكس فوراً على لوحة التحكم (الداشبورد) بدون ما المستخدم يحدث الصفحة.

**مهم جداً:**
- لا تستخدم خطوط عربية مائلة — كل الخطوط لازم تكون واضحة ومستقيمة
- كل عملية تعيين لازم يكون واضح فيها: مين عيّن + لمين + متى
- لما المستخدم ينشئ أوردر جديد — مباشرة بعد الإنشاء يفتح نموذج إنشاء المهمة الأولى (الأوردر يكون محدد تلقائي). يعني الفلو: نموذج أوردر ← إنشاء ← نموذج مهمة أولى ← إنشاء

**السيرفر:** `https://media-center-management-system.onrender.com`
**كل الطلبات لازم يكون معها:** `Authorization: Bearer TOKEN`

---

## فلو إنشاء أوردر جديد (مهم جداً)

### الخطوة 1 — نموذج الأوردر
المستخدم يعبي: العنوان، الوصف، القسم، الأولوية، الوحدة الإعلامية، البرنامج (اختياري)، الموعد النهائي، ملاحظات.
يضغط "إنشاء".

### الخطوة 2 — الفرونت يبعث طلب إنشاء الأوردر
```
POST /api/orders
```
يستقبل الرد فيه رقم الأوردر الجديد.

### الخطوة 3 — مباشرة يفتح نموذج إنشاء المهمة الأولى
الأوردر يكون محدد تلقائي (مش قابل للتغيير). المستخدم يعبي: عنوان المهمة، الوصف، الموظف المعين، الأولوية، الموعد النهائي، نوع المهمة.
يضغط "إنشاء مهمة".

### الخطوة 4 — الفرونت يبعث طلب إنشاء المهمة
```
POST /api/tasks
```

### الخطوة 5 — يوجه المستخدم لصفحة تفاصيل الأوردر
يشوف الأوردر مع المهمة الأولى مضافة.

## صفحة الأوردرات — القائمة `/orders`

### جلب الأوردرات
```
GET /api/orders?limit=10&offset=0
```

### الفلترة
- حسب القسم: `GET /api/orders/desk/:deskId`
- حسب الحالة: `GET /api/orders/status/:statusId`
- حسب البرنامج: `GET /api/orders/program/:programId`
- جلب الحالات المتاحة: `GET /api/orders/statuses`

### التصميم
- جدول فيه: العنوان + الحالة (بلون مميز) + الأولوية + الموعد النهائي + نسبة التقدم (شريط صغير) + تاريخ الإنشاء
- فوق الجدول: فلاتر (قسم + حالة + برنامج) + زر "أوردر جديد"
- الحالات بألوان:
  - Created: رمادي
  - Pending: أصفر
  - In Progress: أزرق
  - Review: بنفسجي
  - Done: أخضر
  - Cancelled: أحمر
- الضغط على صف يفتح تفاصيل الأوردر
- صفحات (pagination) بالأسفل

## نموذج إنشاء أوردر جديد

### التصميم
- نافذة منبثقة (modal) أو صفحة جديدة
- الحقول:
  - العنوان (نص — إلزامي)
  - الوصف (نص طويل)
  - القسم (قائمة منسدلة — إلزامي) — من `GET /api/portal/desks`
  - الأولوية (قائمة منسدلة — إلزامي) — القيم: 1=عاجل، 2=عالي، 3=متوسط، 4=منخفض
  - الوحدة الإعلامية (قائمة منسدلة — إلزامي) — من `GET /api/portal/media-units`
  - البرنامج (قائمة منسدلة — اختياري) — من `GET /api/portal/programs`
  - الحلقة (قائمة منسدلة — اختياري، تظهر لما يختار برنامج) — من `GET /api/portal/episodes?program_id=X`
  - الموعد النهائي (تاريخ)
  - ملاحظات (نص)
- زر "إنشاء"

### الربط
```
POST /api/orders
{
  "title": "...",
  "description": "...",
  "desk_id": 1,
  "status_id": 1,
  "priority_id": 2,
  "media_unit_id": 1,
  "created_by": USER_ID,
  "deadline": "2026-05-01",
  "program_id": 48,
  "notes": "..."
}
```
ملاحظة: `created_by` هو رقم المستخدم الحالي (من التوكن). `status_id` دائماً 1 (Created) عند الإنشاء.

ملاحظة مهمة: إذا اختار برنامج بدون حلقة — بيتنشأ حلقة جديدة تلقائي.

## صفحة تفاصيل الأوردر `/orders/:id`

### جلب التفاصيل
```
GET /api/orders/:id/details
```
الرد فيه: بيانات الأوردر + المهام + نسبة التقدم + تاريخ الحالة

### التصميم — 4 أقسام:

**القسم الأول — معلومات الأوردر:**
- العنوان + الوصف + الحالة (بادج ملون) + الأولوية + الموعد النهائي + القسم + البرنامج/الحلقة
- أزرار الإجراءات:
  - "تغيير الحالة" — قائمة منسدلة بالحالات المسموحة فقط
  - "إلغاء" — يظهر فقط إذا الحالة مش Done أو Cancelled
  - "تعديل" — يفتح نموذج التعديل
  - "حذف" — يظهر فقط إذا ممكن يتحذف (استدعي `GET /api/orders/:id/can-delete` أولاً)
  - "أرشفة" — يظهر فقط إذا الحالة Done

**تغيير الحالة:**
```
PATCH /api/orders/:id/status
{ "status_id": 2, "changed_by": USER_ID }
```

**إلغاء:**
```
PATCH /api/orders/:id/cancel
{ "cancelled_by": USER_ID, "reason": "السبب" }
```

**القسم الثاني — نسبة التقدم:**
- شريط تقدم كبير بالنسبة المئوية
- تحته: عدد المهام (مكتملة / جارية / معلقة)
- البيانات من `progress` بالرد

**القسم الثالث — المهام المرتبطة:**
- جدول بالمهام: العنوان + الحالة + الموظف المعين + الموعد النهائي
- زر "مهمة جديدة" — يفتح نموذج إنشاء مهمة مرتبطة بهاد الأوردر
- الضغط على مهمة يفتح تفاصيلها

**القسم الرابع — تاريخ الحالة:**
- قائمة زمنية: الحالة القديمة ← الحالة الجديدة + مين غيرها + متى
- البيانات من `history` بالرد

## صفحة المهام — القائمة `/tasks`

### جلب المهام
```
GET /api/tasks?limit=10&offset=0
```

### الفلترة
- حسب الأوردر: `GET /api/tasks/order/:orderId`
- حسب الموظف: `GET /api/tasks/assignee/:userId`
- حسب الحالة: `GET /api/tasks/status/:statusId`
- المتأخرة فقط: `GET /api/tasks/overdue`
- جلب الحالات: `GET /api/tasks/statuses`

### التصميم
- جدول فيه: العنوان + الأوردر + الحالة (بلون) + الموظف المعين + الموعد النهائي + الأولوية
- فوق الجدول: فلاتر (أوردر + موظف + حالة + متأخرة) + زر "مهمة جديدة"
- تبويبات سريعة: "الكل" / "المعينة لي" / "المتأخرة"
- "المعينة لي" تستخدم: `GET /api/tasks/assignee/USER_ID`

## صفحة تفاصيل المهمة `/tasks/:id`

### جلب التفاصيل
```
GET /api/tasks/:id/details
```
الرد فيه: بيانات المهمة + التعليقات + المرفقات + العلاقات + التعيينات + التقدم + التاريخ

### التصميم — 6 أقسام:

**القسم الأول — معلومات المهمة:**
- العنوان + الوصف + الحالة + الأولوية + الموعد النهائي + الأوردر (رابط) + الموظف المعين
- أزرار:
  - "تغيير الحالة" — قائمة بالحالات المسموحة
  - "تعيين لموظف آخر"
  - "تعديل"
  - "حذف" (إذا ممكن — `GET /api/tasks/:id/can-delete`)

**تغيير الحالة:**
```
PATCH /api/tasks/:id/status
{ "status_id": 2, "changed_by": USER_ID }
```

**تعيين:**
```
POST /api/tasks/:id/assign
{ "assigned_to": 43, "assigned_by": USER_ID }
```

**القسم الثاني — التعليقات:**
- قائمة التعليقات: اسم الكاتب + النص + الوقت
- حقل إضافة تعليق جديد + زر "إرسال"
```
POST /api/tasks/:id/comments
{ "user_id": USER_ID, "comment": "..." }
```

**القسم الثالث — المرفقات:**
- قائمة المرفقات: اسم الملف + النوع + الوقت + رابط تحميل
- زر "إضافة مرفق"
```
POST /api/tasks/:id/attachments
{ "user_id": USER_ID, "file_url": "https://...", "file_type": "image/jpeg" }
```

**القسم الرابع — العلاقات والتبعيات:**
- قائمة المهام المرتبطة: اسم المهمة + نوع العلاقة (يعتمد على / يحجب / مرتبط بـ)
- زر "إضافة علاقة" — يفتح نموذج لاختيار مهمة ونوع العلاقة
- فحص التبعيات: `GET /api/tasks/:id/dependency` — يعرض إذا المهمة ممكن تبدأ أو محجوبة
```
POST /api/tasks/:id/relations
{ "related_task_id": 10, "relation_type": "depends_on" }
```
أنواع العلاقات: `depends_on` / `blocks` / `related_to` / `subtask_of` / `parent_of`

**القسم الخامس — تاريخ التعيينات:**
- قائمة: مين عيّنها + لمين + متى

**القسم السادس — تاريخ الحالة:**
- قائمة زمنية: الحالة القديمة ← الجديدة + مين + متى

## العمليات الجماعية

### تعيين جماعي
- المستخدم يختار عدة مهام من الجدول (بصناديق اختيار)
- يضغط "تعيين جماعي" — يختار الموظف
```
POST /api/tasks/bulk-assign
{ "task_ids": [1, 2, 3], "user_id": 43, "assigned_by": USER_ID }
```

### تغيير حالة جماعي
- نفس الشي — يختار مهام ويضغط "تغيير حالة"
```
POST /api/tasks/bulk-status
{ "task_ids": [1, 2, 3], "status_id": 2, "changed_by": USER_ID }
```

## الربط بين الأوردرات والمهام

- من صفحة الأوردر — الضغط على مهمة يفتح تفاصيلها
- من صفحة المهمة — الضغط على اسم الأوردر يفتح تفاصيله
- إنشاء مهمة من صفحة الأوردر — الأوردر يكون محدد تلقائي
